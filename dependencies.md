# Зависимость и CVE

## Зафиксированный компонент

- Название: libxml2, upstream GNOME/XMLSoft.
- Версия: **2.11.5**, статическая сборка из исходного архива upstream.
- Архив: https://download.gnome.org/sources/libxml2/2.11/libxml2-2.11.5.tar.xz
- SHA-256: `3727b078c360ec69fa869de14bd6f75d7ee8d36987b071e6928d4720a28df3a6`.
- Официальный список хешей: https://download.gnome.org/sources/libxml2/2.11/libxml2-2.11.5.sha256sum
- Сборка: CMake FetchContent, проверка URL_HASH, target LibXml2::LibXml2.
- Реальное использование: xmlReadMemory разбирает весь документ; xmlGetProp
  извлекает имена/значения; xmlDocGetRootElement и xmlStrEqual обходят дерево;
  xmlFree/xmlFreeDoc освобождают память.

HTTP/FTP, Python, утилиты, тесты, iconv, ICU, zlib, lzma и модули отключены
в CMake. Не используются незафиксированные системные копии libxml2. Системные
libc, libstdc++ и инструментальная цепочка остаются частью окружения Ubuntu.

## Подтверждённая CVE-2024-25062

| Поле | Данные |
|---|---|
| Класс | Use-after-free, CWE-416 |
| Место | xmlValidatePopElement |
| Затронутые версии по NVD | Версии до 2.11.7; ветка 2.12.x до 2.12.5 (включая 2.12.0–2.12.4) |
| Выбранная версия | 2.11.5 попадает в диапазон |
| Исправление этой CVE | 2.11.7 и 2.12.5 в соответствующих ветках |
| Условия | XML Reader API, одновременно DTD validation и XInclude expansion; специально подготовленный XML |
| Возможное последствие | Обращение к освобождённой памяти, аварийное завершение/отказ в обслуживании |

Официальные источники:

1. NVD: https://nvd.nist.gov/vuln/detail/CVE-2024-25062
2. Трекер разработчика, указанный в NVD: https://gitlab.gnome.org/GNOME/libxml2/-/issues/604

Диапазон выше воспроизводит формулировку NVD, а не утверждает, что проверена
каждая историческая версия. Исправленные версии относятся именно к этой CVE:
они не объявляются свободными от всех остальных уязвимостей.

### Применимость к приложению

Версия зависимости затронута, но необходимые условия в данном приложении
отсутствуют: используется DOM API xmlReadMemory, не XML Reader; DTD validation
и XInclude expansion не включены. Документы с DTD отвергаются, а внешний
загрузчик отключён. Поэтому по опубликованному описанию CVE-2024-25062
**не достижима через предусмотренный интерфейс приложения**. Это вывод
из условий advisory и вызовов кода, а не результат эксплуатации CVE.
Чтобы воспроизводить именно эту CVE, потребовался бы другой путь исполнения
с Reader, DTD validation, XInclude и специальным XML. Такой путь не добавлен.

SCA-факт «присутствует затронутая версия» и оценка достижимости — разные
результаты исследования. SCA может найти также другие CVE этой старой версии.

## Проверка реально используемой версии

```bash
./build/rbpo_lab --version
cat build/CMakeFiles/rbpo_lab.dir/link.txt
```

Ожидается:

```text
libxml2 headers: 2.11.5
libxml2 runtime: 21105
```

Первое значение — версия заголовков; второе — переменная из реально
подключённой библиотеки (2 * 10000 + 11 * 100 + 5). При генераторе Unix
Makefiles link.txt должен ссылаться на `_deps/libxml2-build/libxml2.a`.
`ldd` не покажет libxml2.so, поскольку библиотека статическая; это нормально.
Наличие функций и зависимостей можно дополнительно проверить `nm` и link.txt.

## SBOM, Syft + Grype и второй сканер

При конфигурации CMake автоматически создаёт `build/dependencies.cdx.json`:
CycloneDX 1.4, приложение и прямая зависимость, версия, CPE, generic PURL,
ссылка на архив и его хеш. Это **декларативная ведомость собственной сборки**,
не результат автоматического распознавания бинарника и не полный SBOM ОС.
Она генерируется из тех же переменных, что URL и хеш FetchContent.
Хеш в externalReferences относится к исходному архиву, не к libxml2.a.

После установки Syft, Grype и Trivy по официальным инструкциям:

```bash
mkdir -p analysis
syft version > analysis/syft-version.txt
grype version > analysis/grype-version.txt
trivy --version > analysis/trivy-version.txt
syft dir:build -o cyclonedx-json=analysis/syft.cdx.json
grype sbom:analysis/syft.cdx.json > analysis/grype-syft.txt
grype sbom:build/dependencies.cdx.json > analysis/grype-declared.txt
trivy sbom --format json --output analysis/trivy.json build/dependencies.cdx.json
```

Проверьте, появился ли libxml2 и правильная версия в `analysis/syft.cdx.json`.
У C/C++ зависимость, загруженная через FetchContent и статически слинкованная,
может не распознаться автоматически. Пустой отчёт по неполному SBOM не
доказывает отсутствие CVE. Не выдавайте декларативную ведомость за находку Syft.

Grype может сопоставлять CPE с NVD; наличие CPE не гарантирует результат для
любой версии сканера и базы. Trivy принимает CycloneDX, но распознавание
upstream C/C++ из generic PURL/CPE ограничено; он может не сообщить эту CVE.
Это фиксируется как ограничение покрытия, а не как «библиотека безопасна».
Не подменяйте generic PURL выдуманным Debian-пакетом или Conan-пакетом, которого
в сборке нет. Если учебное задание требует именно два положительных нахождения,
потребуется отдельно подобрать и проверить второй сканер с подходящим
сопоставлением upstream-компонента. В текущем проекте два положительных
результата SCA не заявлены.

Официальная документация инструментов:

- https://github.com/anchore/syft
- https://github.com/anchore/grype
- https://trivy.dev/docs/latest/target/sbom/

Скачивание баз SCA может требовать сети; это отдельная стадия анализа.
Запуск приложения и AFL++ сетевых запросов не делает.

## Обновление без изменения приложения

Позже измените одновременно XML_VERSION и XML_SHA256 в CMakeLists.txt,
взяв хеш из официального каталога соответствующего релиза. Создайте новый
каталог сборки, повторите сборку, --version и анализ SBOM. XML_SERIES,
URL, CPE/PURL и версия в SBOM пересчитываются автоматически. Для исправления
конкретно этой CVE достаточно соответствующего исправленного релиза, но
выбор безопасной для эксплуатации версии требует проверки остальных CVE.
Сейчас версия оставлена 2.11.5, никаких исправлений не внесено.
